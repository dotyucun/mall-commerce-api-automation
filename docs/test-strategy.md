# 测试策略

## 风险优先级

本项目不以接口数量作为覆盖目标，而以电商业务风险组织测试：订单归属错误会造成越权，金额和库存错误会造成资产损失，状态机绕过会产生非法履约，异步消息失败会留下长期锁定库存。因此核心断言同时观察 API 响应与持久化事实。

## 断言层次

1. 传输层：请求必须在超时范围内完成，并返回可解析 JSON。
2. 接口层：校验业务码、关键字段、列表结果和错误语义。
3. 业务层：校验金额公式、合法状态迁移、用户所有权和幂等性。
4. 数据层：校验订单主表、明细、SKU 库存、退货记录及操作历史。
5. 异步层：使用轮询等待最终状态，不使用固定长时间 `sleep` 猜测完成时刻。

## 独立性与恢复

- 每个写入型用例前后执行同一套清理，测试不依赖执行顺序。
- 两个专用会员分别验证数据隔离，不修改普通演示账号。
- 商品上下架、SKU `stock` 与 `lock_stock` 在用例结束后恢复到种子基线。
- RabbitMQ 延迟队列在超时用例前清理，避免旧消息造成队头阻塞。
- 所有数据库写操作只允许出现在 `TestDataManager`，业务场景通过真实接口改变状态。

## 已知缺陷原则

只有已通过源码和运行结果确认的缺陷才能标记 `xfail(strict=True, raises=KnownDefectError)`。每个标记必须关联 Issue；专用异常只在确认缺陷的 API 与数据库特征后抛出。其他断言和环境故障不能被接受为预期失败。缺陷修复后会 XPASS 并使流水线失败，提示维护者移除标记。

## 性能边界

Locust 场景采用 20 用户、每秒启动 2 个、持续 2 分钟，目标为失败率低于 1%、P95 小于 1000ms。该结果只能说明固定本机环境下的轻量基线，不能外推生产容量。

每个请求检查 HTTP 状态、业务码和关键数据：登录 Token、搜索中的专用商品、详情商品 ID、购物车列表类型。HTTP 200 但业务失败或内容错误计入失败率；没有请求样本也不得通过。性能任务不与业务回归同时执行。
