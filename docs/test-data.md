# 测试数据治理

## 专用数据

Compose 初始化脚本创建两名自动化专用会员 `autotest_a`、`autotest_b` 和独立收货地址。商品使用固定 `product_id=26`、`sku_id=110`，并设置唯一搜索关键字 `AUTOTEST_PRODUCT_P20`，避免依赖默认中文商品名。

测试代码不散落这些 ID。它们由 `default.yaml` 进入 `Settings.fixture`，再通过 fixture 注入 Workflow。

## 清理范围

`TestDataManager.reset()` 只处理专用用户和固定商品：

- 删除专用用户购物车、订单明细、订单操作记录和订单主表。
- 删除关联退货申请。
- 恢复固定商品为上架状态。
- 恢复 SKU 基线库存并清零锁定库存。
- 恢复默认订单超时时间。
- 清理 RabbitMQ 订单延迟队列中的历史测试消息。

测试不会全表清空，也不会清理非专用会员的数据。

## 凭据管理

YAML 只存放 URL、端口、用户名、固定 ID 等非敏感默认值。密码从 `.env` 或 CI Secrets 注入，`.env` 被 Git 忽略。`.env.example` 仅声明变量名，不提供值。

## 数据库写入边界

测试数据预置和恢复允许直接写库，因为这是测试环境治理；业务动作必须调用真实前后台接口。该边界防止用 SQL 伪造“接口已经完成业务”的结果。
